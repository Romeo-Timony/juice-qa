# 🏛️ Архитектура тестового комплекса OWASP Juice Shop (ISTQB & Senior AQA Standard)

Настоящий документ определяет целевую иерархию папок, правила декомпозиции тестов, распределение по слоям пирамиды тестирования и триггерную политику развития фреймворка автоматизации.

---

## 1. Слои пирамиды тестирования (Test Pyramid Hierarchy)

```
                            /\
                           /  \
                          / E2E\          tests/e2e/ (Сквозные бизнес-сценарии)
                         /------\
                        /   UI   \        tests/ui/ (Компонентные тесты экранов POM)
                       /----------\
                      /    API     \      tests/api/ (Интеграционные тесты REST API)
                     /--------------\
                    /      UNIT      \    tests/unit/ (Самотестирование фреймворка, <10мс)
                   /------------------\
```

---

## 2. Полная структура каталогов `qa-automation/tests/`

```text
tests/
│
├── unit/                                  # Слой 1: Unit-тесты компонентов самого фреймворка (<10мс, без сети)
│   ├── api_client/                        # Тесты JuiceShopApiClient: сборка cURL, заголовки, таймауты
│   ├── data_models/                       # Тесты датаклассов: UserPersona, валидация DTO, иммутабельность
│   ├── utils/                             # Тесты утилит: decode_jwt_payload, хеширование, парсеры
│   └── fixtures/                          # Тесты фабрик и генераторов тестовых данных
│
├── api/                                   # Слой 2: REST API интеграционные тесты по доменам Juice Shop
│   ├── auth/                              # Регистрация, логин, JWT, 2FA, смена пароля (JS-17)
│   ├── catalog/                           # Продукты, поиск, отзывы, лайки, рейтинги (JS-19/20)
│   ├── basket/                            # Корзина, добавление товаров, количество, купоны
│   ├── orders/                            # Создание заказа, трекинг, история заказов, накладные
│   ├── wallet/                            # Цифровой кошелек: баланс, пополнение, списание
│   ├── deluxe/                            # Подписка Deluxe, проверка прав и списания $49
│   ├── user/                              # Личные данные, адреса доставки, платежные карты, GDPR
│   ├── administration/                    # Админка: аудит пользователей, метрики, captcha
│   └── personas/                          # Тестовые персоны: Admin, Jim ($100), Bender ($0), RBAC
│
├── ui/                                    # Слой 3: UI-тесты страниц через Page Object Model (Playwright)
│   ├── auth/                              # Формы Login, Register, Forgot Password, 2FA (JS-16)
│   ├── catalog/                           # Страница поиска, карточки товаров, фильтры
│   ├── basket/                            # Экран корзины, ввод промокода
│   ├── checkout/                          # Выбор адреса, способ доставки, метод оплаты
│   ├── profile/                           # Профиль пользователя, загрузка аватара, адреса/карты
│   ├── administration/                    # Экран /#/administration, Score Board
│   └── recycle/                           # Страница переработки Recycle, Photo Wall
│
├── e2e/                                   # Слой 4: Сквозные пользовательские сценарии (User Journeys)
│   ├── customer_journeys/                 # Полноценная покупка: Поиск -> Корзина -> Кошелек -> Инвойс
│   ├── guest_journeys/                    # Флоу гостя: просмотр -> корзина -> принудительный логин
│   ├── deluxe_journeys/                   # Сквозной апгрейд аккаунта до Deluxe и проверка привилегий
│   └── admin_journeys/                    # Сценарии администратора: аудит отзывов, модерация
│
└── qaops/                                 # Слой 5: Внутренние швы контроля качества пайплайна (Seams 1-6)
```

## 3. Политика триггеров развития Unit-тестов фреймворка (Framework DoD Trigger Policy)

Чтобы исключить деградацию и регресс самого тестового кода, внедрен **Definition of Done (DoD) триггер**:

| Событие в кодовой базе AQA | Обязательное действие (Триггер) | Папка назначения |
| :--- | :--- | :--- |
| **Добавление метода в `api/client.py`** | Написать unit-тест на формирование URL, сериализацию параметров и заголовков. | `tests/unit/api_client/` |
| **Создание новой модели данных в `data/`** | Написать unit-тест на проверку типов, значений по умолчанию и иммутабельности. | `tests/unit/data_models/` |
| **Добавление утилиты/парсера в `core_utils/`** | Написать unit-тест с покрытием граничных значений (BVA) и эквивалентных классов. | `tests/unit/utils/` |
| **Добавление сложной фикстуры в `conftest.py`** | Написать unit-тест на корректность генерации и teardown. | `tests/unit/fixtures/` |

---

## 4. Скрипты запуска по слоям

* **`run_unit_tests.bat`** — запуск Unit-тестов фреймворка (время прогона `< 2 сек`).
* **`run_backend_tests.bat`** — запуск REST API тестов (`tests/api/`).
* **`run_frontend_tests.bat`** — запуск UI компонентных тестов (`tests/ui/`).
* **`run_e2e_tests.bat`** — запуск сквозных пользовательских цепочек (`tests/e2e/`).
* **`run_allure_report.bat`** — генерация единого интерактивного Allure Report со скринкастами.
